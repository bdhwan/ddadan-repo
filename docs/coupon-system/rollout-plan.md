## 배포 순서 (§20.2)

상세 주의사항·헬스·백업은 [runbook.md](./runbook.md) 를 본다. 요약만 옮긴다.

1. 확장 가능한 DB migration 적용
2. worker와 API를 이전/신규 schema 동시 호환 버전으로 배포
3. Angular 앱 배포
4. 새 기능 flag 활성화
5. 비호환 컬럼 정리는 최소 한 릴리스 뒤 별도 migration

## 단계적 출시 (§20.3)

| 단계 | 범위 | 다음 단계 진입 조건 |
|---|---|---|
| 1 | 내부 계정·테스트 상점 | 중복 거래 0, 미해결 심각 민원 0, 복구 훈련 성공 |
| 2 | 협력 카페 1곳, 소비자 50명 이하 | 동일 |
| 3 | 상점 10곳, 선착순 캠페인 제한적 활성화 | 동일 |
| 4 | 알림톡 심사·비용·수신거부 검증 후 채널 활성화 | 동일 |
| 5 | SLO·민원·부정사용 지표 충족 시 일반 가입 | — (일반 출시) |

각 단계는 **중복 거래 0**, **미해결 심각 민원 0**, **복구 훈련 성공**을 다음 단계 조건으로 둔다(§20.3).

## 기능 플래그 (§20.4)

- 카카오 로그인
- FCM Web Push
- 카카오 알림톡
- 선착순 캠페인

플래그 저장소·토글 절차·환경별 기본값: 미정 ([runbook.md](./runbook.md) 동일).

## 알려진 한계 (커밋 `7a1b682`)

- 통합 테스트를 같은 DB에 반복하면 `the_review_queue_activates_a_store_on_approval` 이 깨질 수 있다. 검수 큐를 `limit=100` 으로 조회해 방금 만든 건을 찾는데, 누적된 PENDING이 100건을 넘으면 첫 페이지 밖으로 밀린다. DB를 초기화하면 통과한다. → [runbook.md](./runbook.md) 「테스트 DB 누적」.
- 알림톡은 대행사 템플릿 승인 전이라 `TEMPLATE_UNAVAILABLE` 로 억제된다.
- Firebase 세션 폐기의 provider 호출은 서비스 계정 키가 들어오면 붙인다. 우리 쪽 `sessions_valid_after` 로는 이미 즉시 차단된다.
- `COUPON_EXPIRING` 의 정보성/마케팅 분류는 출시 전 심사 대상이다(§23.2).
- `/me/withdrawal` 과 `/public/stores` 계열은 스펙에 있으나 이번(Phase 4) 범위가 아니다. openapi `paths` 에도 없다 → [api-endpoints.md](./api-endpoints.md).
